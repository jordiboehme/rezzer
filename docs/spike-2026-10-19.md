# Crate spike, 2026-10-19

Throwaway spike to pick the crates for sub-project 1 (core). Three agents each collected a public
test corpus and scored crates against an intent checklist: what structure, metadata and hidden
logic (formulas, form calculations, fields, tracked changes, link and reply graphs) the API
exposes, not how nice the printed Markdown is. Spike code stays in the gitignored `spike/`
folder. Detailed reports and corpus manifests (source URL, license and SHA-256 per file) are in
[`spike-2026-10-19/`](spike-2026-10-19/).

Versions were checked on 2026-10-19. Re-check them before relying on them.

## Main result

No crate covers the knowledge layer. Values and text are solved by crates; the logic around them
(formulas with references, form calculations, comments with threads, tracked changes, fields,
validation, embedded data) Rezzer mostly reads itself, with zip + quick-xml for OOXML and ODF and
lopdf for PDF objects. This confirms approach A: own document model, thin readers, one renderer.

## Ruled out or kept only as reference

- Xberg: no fallback. Caps formula metadata at 200 per sheet with wrong cell addresses, wrong
  two-column order, loses EPUB roles and series, treats PostScript as source code, picks formats
  by extension. Its CLI archive bundles a GPL x265 library. Kept only to compare output
- pdf_oxide: richest PDF model, but huge, pre-1.0, slow to build and showed defects on the small
  corpus (lost annotations, reversed Arabic word)
- docx-rs, umya-spreadsheet, ooxmlsdk, spreadsheet-ods, undoc: bugs, crashes or missing parts (see
  office.md)
- ferrodoc-docx: claims a port of GPL pandoc code, provenance risk
- htmd, html-to-markdown-rs: Markdown strings or flattened structure
- qsv-sniffer: wrong on 8 of 13 CSV files, repository archived

## Security findings

- stet has no safe mode: PostScript can delete and read files. Only in a sandboxed child process
- Office decompression bombs: undoc and spreadsheet-ods used several GB on hostile files, ooxmlsdk
  overflowed its stack. Rezzer's readers need size, depth and time limits from the start

## Licenses

All recommended crates and their dependency trees are permissive. zip with the bzip2 feature needs
a cargo-deny allow entry for the bzip2-1.0.6 license. stet's bundled URW fonts have an unclear
license.

## Open gaps in the corpus

No public file found for some cases (PDF annotation replies, some form calculations, iterative
calculation, hidden slides, Word table formulas, DOCX gridSpan). Those cells were scored from the
crate API or source only and are marked in the reports.

## Mathcad and SMath

Separate research in [`research/2026-10-19-mathcad.md`](research/2026-10-19-mathcad.md): Prime
`.mcdx`, `.xmcd` and SMath `.sm` are readable (formula trees and cached results are stored), binary
`.mcd` is not. Not part of the core; Excel and LibreOffice are the engineering sheets for now.
