# CAD spike part A: native MCAD and exchange formats (group `mcad`, 2026-10-19)

Scope: FreeCAD `.FCStd`, STEP AP203/214/242, IGES, Fusion 360 `.f3d`, the "L1" native formats
(SolidWorks, Inventor, Creo, NX, CATIA, Rhino `.3dm`, ACIS `.sat`). Candidates: cadmpeg 0.6.2
(all codecs plus `cadmpeg-registry`), stepq 0.6.0, step-io 0.2.5, and three own readers
(FCStd with zip + quick-xml, Part 21 tokenizer, IGES fixed-column reader).

Probes: `spike/cad-test/mcad/` (`p-cadmpeg`, `p-stepq`, `p-step-io`, `p-own-fcstd`, `p-own-p21`,
`p-own-iges`, `run.sh`, `scripts/gen_synthetic.py`, `scripts/licenses.py`, raw output in `out/`).
Corpus: `spike/corpus/cad/mcad/` (34 MB, 60 files, `MANIFEST-part.md`).

Course correction applied: Rezzer runs every reader in-process. This report recommends no
external program (no FreeCAD, no OpenCascade). Exact volume, mass and exact bbox are "not
available" unless a reader states them in the file.

## 1. Short answer

| Format | Recommendation | First release? |
|---|---|---|
| FreeCAD `.FCStd` | **Own reader** (zip + quick-xml, 263 lines in the probe) as the base. cadmpeg-codec-freecad as an optional enricher only after its "whole file refused" bugs are fixed | Own reader: yes |
| STEP AP203/214/242 | **stepq** for product structure, BOM, placements, properties and semantic PMI, plus a small own layer for colours, layers, graphic PMI counts and the vertex bbox (the own tokenizer shows this is about 180 lines) | Yes |
| IGES | **Own fixed-column reader** (88 lines) for start text, global fields, units, entity histogram, levels, names, notes. cadmpeg-codec-iges does not expose these in its neutral model | Yes |
| Fusion 360 `.f3d` | cadmpeg-codec-f3d: real feature tree with operation semantics, sketches, parameters, materials. Joints and user parameters not shown on our files | Later (behind a feature flag) |
| SolidWorks `.sldprt` | cadmpeg-codec-sldprt: far above its "L1" label on a real SW 2018 file (features, sketches, parameters, semantic PMI). Assemblies: no structure | Later (feature flag) |
| Creo / NX / CATIA / Inventor / Rhino / SAT | cadmpeg gives metadata, units, part number, preview, some features/parameters (Creo, NX), layers/groups (Rhino) mostly in its `native` namespace. Inventor needs a detection workaround | Later; first release: say "native format, ask for STEP AP242" plus what cadmpeg-registry can identify |

Key reasons:

- cadmpeg's model is the best semantic model in this spike (design arenas, losses, stable IDs),
  but it costs a 100 MB probe binary, decodes all geometry even when Rezzer wants only design
  data (44 s and 3.1 GB RSS for a real 20.6 MB FCStd; timeout at 60 s with 1.7 GB for a
  58.9 MB FCStd), and refuses a whole document on one unexpected property (the real FreeCAD 1.0
  Assembly file `bldc_BLDCM.FCStd`, plus the deliberately broken f3d-app fixture and the
  synthetic cyclic file). Of 10 independent FCStd files (7 in the corpus, 3 large ones in the
  scratchpad) cadmpeg refused 2 and timed out on 1. The own FCStd reader reads all of them in under 50 ms and under 40 MB.
- stepq is small (1.1 MB probe), fast (49 MB STEP in 0.23 s), MIT, and its PMI values match
  the NIST definitions. step-io drops tolerance magnitudes and dimension values on NIST files.

## 4. Do cadmpeg's self-scored levels hold?

Cross-format table for the same NIST part CTC-01 (cadmpeg 0.6.2, full decode; STEP columns
for comparison). NIST definition: datums A, B, C; tolerances: 2 surface profile, position
0.75 A|B|C, flatness 0.2, perpendicularity 1.5 A; size dimensions ⌀20, ⌀25 ±0.15, ⌀34.8-35.2,
⌀35, 60° ±0.5°.

|---|---|---|---|---|---|---|---|
| cadmpeg self-score | - | L9 | L1 | L1 | L1 | L1 | L1 |
| Detected | - | yes | yes | yes | yes | yes | **no** (forced codec works) |
| Units | mm, degree | mm | mm | mm (`principal_unit` mmKs) | mm | mm | mm |
| Part number / name | product "NIST Test Case 1" | yes | file path in `sw_name` | `model_name` | attribute "Part Number" | no | `part_number`, `author` |
| Custom properties | Modeled By, CAGE Code, Company | native only | 4 attributes (records, not props) | no | Description, Revision, Part Number | no | native, "9 property values without neutral mapping" |
| Faces | 117 | 117 | 137 | 38 neutral faces (111 face admissions rejected) | 0 (topology "not reconstructed") | 117 | 139 |
| Features | - | - | 47 (extrude, hole, fillet, chamfer, sketch, datums) with operation parameters | 30 (Protrusion, Round, Hole, Cut, Chamfer, datum planes) | 38 (EXTRUDE, SIMPLE HOLE, CHAMFER, BLEND native) | 3 unresolved | 0 |
| Parameters | - | - | 97 (D1 = 50, R10, 45°) | 144 (d8 = 50) | 88 (p0 = 225) | 0 | 0 |

| Semantic PMI | 3 datums, 6 tol, 12 dims | 3 + 2 datum systems, 6, 12 (+23 graphic) | **19: 3 datums, 2 systems, 6 tol (position 0.75 ✓), 8 dims** | 0 | 0 (PMI streams "opaque") | 0 | 0 |
| Losses reported | - | 33 | 4 | 23 | 25 | 4 | 4 |

Verdict:

- **STEP (L9)**: holds for reading structure, PMI and losses. Semantic PMI counts match stepq
  and step-io exactly (12/6/3); cadmpeg's `pmi=46` adds 23 graphic "presentation" entries and
  `drawings=25` are the draughting callouts, both correctly labelled. Dangling references
  become explicit losses (`instance #5 omitted: unresolved instance reference #999`).
- **FreeCAD (L5)**: holds on the files it accepts, including the independent spreadsheet file
  (aliases, `Pad.Length` depends on cell B9, cross-document expression text kept). Refuses the real
  FreeCAD 1.0 Assembly file `bldc_BLDCM.FCStd` and the deliberately broken f3d-app fixture;
  times out on a real 58.9 MB file (section 9).
- **f3d (L4)**: holds: features with operation semantics (extrude extents, fillet radius),
  sketches with dimension constraints linked to parameters, components and occurrences,
  physical material properties (density 7850, yield stress). The codec has a joint decoder
  (`project_assembly_joints`) and a loss code `assembly.joint-unprojected` (src), but on "Ball
  Joint" and "Sample Joint v3" no joint and no joint loss appears: a silent gap (bug 7). Nested
  occurrences are "not placed" (a loss says so). User parameters are decoded in source order
  with units and dependencies (src); no corpus file had any.
- **SolidWorks (L1)**: understated. On the real SW 2018 MBD part it is effectively L6 for parts:
  feature tree, parameters with values, sketches with constraints, the configuration
  "Default", and semantic PMI that matches NIST. On the NIST SLDASM (not in corpus) it produced
  130,356 sketch entities, 681 MB RSS, 1.4 s, but **no occurrences and no product structure**.
- **Creo (L1)**: understated for features and parameters (named features "Hole id 2078",
  144 `dNN` parameters with values, 549 sketch constraints), but B-rep is incomplete (38 of 117
  faces) and there is no PMI. Same result for Creo 4 and Creo 10.
- **NX (L1)**: features and parameters, attributes Part Number/Description/Revision, preview
  JPEG; no topology, PMI streams opaque. NX assembly (MTC, not kept): component occurrences and
  32 external references only in `native[nx]`.
- **CATIA (L1)**: holds: geometry and faces, no design data, no properties.
- **Inventor (L1)**: holds after forcing the codec: author, part number, description (`.iam`),
  preview, geometry. Parameters only on one of 5 files (479 `dNN` on keyPlate.ipt);
  `global_params.ipt`, which holds the user parameters of the RespiraWorks project, gives 0.
  Assembly occurrences (6) only in `native[inventor]`; external reference table "malformed".
- **Rhino (L1)**: geometry plus application name ("Rhinoceros 6, Educational Lab License"),
  tolerances, units; layers, groups, object names and dimension styles only in
  `native[rhino]` and as flat `source.attributes` strings (`layer.1.name`).
- **SAT (L1)**: geometry only (NIST MTC cover: 377 faces, 165 unknown records).

## 5. Scoring: FreeCAD `.FCStd`

Applicable: all core items except PMI and print settings. N/A: GD&T (FreeCAD has none in the
model), slicer settings.

Legend: E exposed in the public API, P partial (why), N not exposed, - not supported.
"native only" = reachable only in cadmpeg's per-format `native` namespace (raw records,
sometimes raw XML); that would tie Rezzer to codec internals, so it scores P.

| Item | cadmpeg-codec-freecad | own reader (zip + quick-xml) |
|---|---|---|
| Object types and labels | E (`features` with `source_tag`, names) | E |
| Feature operation semantics (Pad, Pocket, Fillet, Hole, Part primitives) | E (typed `extrude` with extent, profile, direction; `post_process`) | P (raw property values: Type, Length, Midplane; own mapping needed per type) |
| Feature dependency DAG | E (`dependencies`, ordinals) | E (ObjectDeps, links); P on 0.17 files without ObjectDeps |
| ExpressionEngine entries | E (parameter `expression` text) | E |
| Parameter dependency edges ("which drives which") | E (`dependencies` resolved to spreadsheet cells) | E (33 edges on levity file, alias to cell, external refs counted, cycle check) |
| Spreadsheet cells, aliases | E (`spreadsheets` + cell parameters with `alias`) | E |
| Sketch geometry | E (typed sketch entities) | P (types and counts; coordinates are in the XML) |
| Sketch constraints with values | E (kind, parameter, driving) | E (type, value, driving) |
| Named constraints | E (field present; no named constraint in any real file) (src) | E (field read; none named in corpus) |
| Placement | E | E |
| Materials | P (native only, `ShapeMaterial` uuid) | P (uuid only; needs FreeCAD material library) |
| Appearance (GuiDocument) | E (`appearances`, bindings) | P (colours; per-face colour files not decoded) |
| App::Link and external links | E (occurrences; external component) | E (link target, `file#object`, placement) |
| Assembly workbench joints | E (`assembly_joints`, 17 on AssemblyExample) | P (joint type code and refs) |
| TechDraw pages, dimensions, template texts | E (`drawings`, `semantic_annotations`) | P (objects and types; EditableTexts read, none in corpus) |
| Metadata (CreatedBy, Company, License, dates, ProgramVersion) | P (ProgramVersion E; the rest native only as raw XML) | E |

| Losses | E (machine-readable) | P (own messages) |

## 9. Bugs found

cadmpeg 0.6.2:

1. **Inventor detection fails on all 6 real files** (NIST Inventor 2021, RespiraWorks,
   MXKeyboard). `InputCatalog::resolve_seekable_source` returns `Unrecognized`. Likely cause (from the
   doc comment, not verified): deeper probing only builds a ZIP detection image, and the CFB
   prefix probe does not see the RSeStorage entries. Forcing the codec decodes fine. Workaround:
   force `inventor` for CFB files with `.ipt/.iam` extension.
2. **Whole FCStd refused on one odd property**: FreeCAD 1.0 Assembly file `bldc_BLDCM.FCStd`:
   `malformed container: joint parameter property ...Joint:AngleMax has runtime type
   App::PropertyFloat, expected App::PropertyAngle`. A loss would be correct, not a refusal.
3. **Whole FCStd refused on broken links** (`f3dapp_broken_links.FCStd`, and the synthetic
   cyclic file): "ObjectDeps records do not match the Objects dependency envelope".
4. **Full decode is the only way to get design data, and it decodes all geometry**: real
   20.6 MB FCStd (MXKeyboard): 44.1 s, 3.15 GB RSS; real 58.9 MB FCStd (wheel_leg_v6, 312
   expressions): killed at 60 s with 1.69 GB; 32.3 MB FCStd: 4.6 s, 1.08 GB. Own reader:
   0.03 to 0.05 s, 8 to 36 MB.
5. 49 MB STEP: 4.7 s and 1.08 GB RSS (stepq 0.24 s / 470 MB).
6. SLDASM (NIST MTC, not kept): 130,356 sketch entities, no occurrences, 681 MB RSS.
7. f3d joints in two files with joints are neither projected nor reported as a loss,
   although the codec has a joint decoder and a `assembly.joint-unprojected` loss code.
   Nested occurrences not placed (reported as a loss).
8. Inventor `global_params.ipt`: user parameters not decoded, no loss names them.
9. IGES 212 general note with a valid parameter list is "not projected" (text, metrics or use
   flag judged invalid); text only in native namespace as hex.
10. Truncated IGES and truncated FCStd: whole file refused. Truncated STEP: decodes with 355
    precise losses (good).

stepq 0.6.0: no bug found. `Graph::new` is strict on dangling references (good), the caller
must fall back to `Graph::build`.

step-io 0.2.5: tolerance magnitudes given as complex measure instances (normal in NIST AP242
files) return `None`; dimension values `None` on the same file; dangling references are not
reported at all (read ok).

Own readers (spike quality): expression paths starting with `.` print as `Sketch001..Attach...`;
FreeCAD ObjectDeps graphs contain Body/feature back-links, so the "object cycle" flag is true
on normal files and must use Group/BaseFeature instead.

## 10. Robustness

Every pair ran in its own process, 20 s alarm, `/usr/bin/time -l` (`out/results.tsv`; cadmpeg
in no-JSON mode).

## 12. How Rezzer should present this knowledge

- **Frontmatter**: format and producing system (`originating_system`, `ProgramVersion`,
  Rhino licence string), units, author, organization, dates, license (FreeCAD `License`).
- **Feature tree**: Mermaid `flowchart TD` from the dependency DAG (Sketch --> Pad --> Pocket),
  node label = name plus operation and key value ("Pad 2 mm symmetric"). Suppressed features
  dashed.
- **Parameters**: table name | value | unit | expression | driven by. A second Mermaid graph
  only for the parameter edges ("Spreadsheet.car_width (B2) --> Sketch constraint 80"), with
  cross-document references as external nodes and cycles marked.
- **Spreadsheets**: table of aliased cells first (alias, cell, value, formula), then a count of
  the rest.
- **Sketches**: one line per sketch: geometry counts, constraint counts by type, list of
  driving dimensions with names and values.
- **Assembly / BOM**: indented BOM table with total quantities (stepq `bill_of_materials`) and a
  Mermaid tree of components; placements in a collapsed table. Joints as a table (type, parts).
- **PMI**: table per tolerance (type, value, modifiers, datum reference frame, target faces),
  datums, dimensions with tolerance; say if PMI is only graphic.
- **Geometry**: one line: bodies, faces, vertex bbox in file units, "exact volume: not
  available".
- **What could not be read**: list of losses, grouped by code, with counts; for native
  formats the advice to ask for STEP AP242.

## 13. Risks

- cadmpeg changes daily (100+ commits in 90 days, IR version 6); results here are for 0.6.2.
- The cadmpeg FreeCAD fixtures are generated by cadmpeg itself; cadmpeg's good results on them
  say little. The independent files are the better test.
- stepq has one maintainer and 1 star; keep it behind Rezzer's STEP reader trait with reference
  files (NIST CTC/FTC) and expected output.
