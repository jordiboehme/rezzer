# Rezzer research: Mathcad, SMath Studio and other calculation worksheets

Date: 2026-10-19. Question: can Rezzer read engineering calculation worksheets from Mathcad
and similar tools without the vendor's software, legally and reliably, and extract their
hidden logic (variables, definitions, expressions, units, inputs and results, dependencies,
text, plots, metadata)?

Method: 18 public sample files (MIT or CC0, listed in
`spike/corpus/mathcad/MANIFEST-mathcad.md`) were unzipped and read as XML with small
read-only Python scripts kept outside the corpus folder. Repositories and licenses were
checked with the GitHub API on the report date. Legal texts were read from the primary
source (PTC agreement PDFs, SMath terms page, CJEU judgment on EUR-Lex, Directive text via
legislation.gov.uk). Only MIT, CC0 or unlicensed-but-public README text was read; no GPL,
no-license or vendor code was opened (see section 7). Claims marked **[unverified]** come
from forum posts, my own knowledge or a single source, and were not confirmed.

This is a research note, not legal advice.

## 1. Summary

| Format | Container | Readable without vendor software? | Results cached in file? | Feasibility for Rezzer | Effort (first useful reader) |
|---|---|---|---|---|---|
| Mathcad Prime `.mcdx` (Prime 3 to 12 seen) | OPC zip (ECMA-376 Part 2) with XML parts | Yes. Expressions are a clean content-math tree, units are tagged, results in `result.xml` | Yes, per region, in SI base units, with status `Synchronized` or `Pending` | **High** | 3-4 weeks for math, text, results, units, plots, dependency graph |
| Mathcad 12-15 `.xmcd` | Single XML file, base64 items inside | Yes for math, text, results, metadata. Plots are an opaque binary blob, but every region has a PNG rendering | Yes, inline in the `<ml:eval>` element | **High** for logic, **Low** for plot data | +1-2 weeks on top of `.mcdx` (shared expression model) |
| Mathcad 11 and older `.mcd` | Proprietary binary | No public spec, no open parser found | Unknown | **Not feasible** now. Say so, suggest PTC's converter | Out of scope |
| SMath Studio `.sm` | Single XML file | Yes. Expressions in postfix (RPN) token lists | Yes, `<result action="numeric">` with display unit | **High** | 1-2 weeks |
| Calcpad `.cpd` | Plain text (MIT tool) | Yes, it is source code | No (needs the engine) | Medium | Parser only: ~1 week |
| Jupyter `.ipynb` | JSON, open spec | Yes | Yes (outputs) | High, but not a "calc sheet" case | Small |

Bottom line: Mathcad Prime and SMath are good fits for Rezzer's core principle. The files
are not just pictures of math: they carry the full expression tree with typed identifiers
(`VARIABLE`, `UNIT`, `FUNCTION`, `CONSTANT`), the definition operator, the display unit
override and the last computed value. Rezzer does not need a Mathcad engine to report what
the sheet defines, how, and what it computed last time. It needs one only to recompute,
which it should not try.

## 2. Mathcad Prime `.mcdx`

### 2.1 Facts

- Current release: PTC Mathcad Prime 12, available since 2026-04-08
  ([PTC help, What's New 12.0.0.0](https://support.ptc.com/help/mathcad/r12.0/en/PTC_Mathcad_Help/whatsNewMathcadPrime.html),
  [PTC blog](https://www.ptc.com/en/blogs/cad/mathcad/whats-new-mathcad-prime-12)). The
  newest sample (`mcad2py_header_footer.mcdx`) says `appVersion 12.0.0.1`, build
  `2026.04.23.001`.
- PTC's help lists MCDX only as "Native PTC Mathcad file format for worksheets" under
  "XML-based file formats" and gives no schema or structure
  ([About File Formats, r12](https://support.ptc.com/help/mathcad/r12.0/en/PTC_Mathcad_Help/about_file_formats.html)).
  **No public schema or format documentation from PTC was found.**
- The container is an Open Packaging Conventions zip, the same as DOCX/XLSX. The content
  types even use the OOXML-style prefix
  `application/vnd.openxmlformats-officedocument.mathprocessingml.mathcad.*`. The container
  is an open standard; the XML vocabularies inside are PTC's own.
- Namespaces have stayed the same from Prime 3 (2013) to Prime 12 (2026). Only the minor
  schema versions in `docProps/app.xml` grow:

| Sample | appVersion | build | Worksheet schema | Math schema |
|---|---|---|---|---|
| coolprop_CoolPropFluidProperties | 3.0.0.0 | 2013.09.12 | 5.3.10 | 5.3.2 |
| mpt_JSON | 4.0.0.0 | 2017.02.26 | 5.4.4 | 5.4.2 |
| netefi-mp6 | 6.0.0.0 | 2019.09.17 | 5.6.1 | 5.4.2 |
| mcad2py (7 files) | 11.0.1.0 | 2025.08.22 | 5.10.7 | 5.10.9 |
| mcad2py_header_footer | 12.0.0.1 | 2026.04.23 | 5.11.2 | 5.10.9 |

  Prime 1.0 and 2.0 were not seen **[unverified]**: same namespaces are likely but not
  confirmed.

### 2.2 Package parts

```
[Content_Types].xml
_rels/.rels                        -> worksheet.xml, header.xml, footer.xml, core.xml
docProps/core.xml                  dc:creator, cp:lastModifiedBy, cp:revision
docProps/app.xml                   appVersion, engineVersion, build, culture, schema versions
mathcad/worksheet.xml              regions: math, text, plot, picture, Area, solveblock, ...
mathcad/_rels/worksheet.xml.rels   ids -> xaml/*.XamlPackage, media/*
mathcad/result.xml                 cached results per resultRef
mathcad/header.xml, footer.xml     same region model as the worksheet
mathcad/settings/calculation.xml   unit system, ORIGIN, tolerances, auto-calc
mathcad/settings/presentation.xml  number formats, styles
mathcad/integration.xml            (empty in all samples)
mathcad/xaml/FlowDocumentN.XamlPackage   text region content, itself an OPC zip
mathcad/media/*                    pictures (per mcad2py notes; Prime mislabels BMP as .png)
```

### 2.3 Math regions

A definition with a unit (`RC_col.mcdx`, Prime 11):

```xml
<region region-id="2" top="56.69" left="198.43" actualWidth="61.1" actualHeight="22.4">
  <math resultRef="0">
    <ml:define>
      <ml:id labels="VARIABLE" xml:space="preserve">
        <Span xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation">w<pw:Subscript>c</pw:Subscript></Span>
      </ml:id>
      <ml:apply>
        <ml:scale/>
        <ml:real>1.3</ml:real>
        <ml:id labels="UNIT" label-is-contextual="true" xml:space="preserve">m</ml:id>
      </ml:apply>
    </ml:define>
  </math>
</region>
```

A definition that also shows its value (`h_c := z - (FUK + t) =`). The `<ml:unitOverride>`
holds the display unit, a `<ml:placeholder/>` means "automatic":

```xml
<math resultRef="7">
  <ml:define>
    <ml:id labels="VARIABLE">h<pw:Subscript>c</pw:Subscript></ml:id>
    <ml:eval>
      <ml:apply>
        <ml:minus/>
        <ml:id labels="VARIABLE">z</ml:id>
        <ml:parens><ml:apply><ml:plus/><ml:id labels="VARIABLE">FUK</ml:id><ml:id labels="VARIABLE">t</ml:id></ml:apply></ml:parens>
      </ml:apply>
      <ml:unitOverride><ml:placeholder/></ml:unitOverride>
    </ml:eval>
  </ml:define>
</math>
```

Element inventory over the 10 Prime samples (top of the list): `ml:id` 2174, `ml:apply`
1231, `ml:real` 769, `region` 534, `math` 425, `ml:eval` 233, `ml:define` 230,
`ml:unitOverride` 233, `ml:localDefine` 159, `ml:program` 124, `ml:matrix` 95,
`ml:function` 36, `ml:range` 24, `ml:summation` 18, `ml:lambda` 18, `ml:if`/`then`/`else`,
`ml:for`, `ml:while`, `ml:tryCatch`, `solveblock`, `Area`, `plot`/`xyPlot`, `spec-table`,
`pageBreak`. Identifier roles seen: `VARIABLE` 1789, `FUNCTION` 251, `UNIT` 148, `*` 60,
`CONSTANT` 27, `KEYWORD` 2, `SYSTEM` 1.

This is content markup in the spirit of MathML content: operator first, then operands. Names
with subscripts are WPF `Span` fragments and need flattening (`w_c`). mcad2py notes that
`ml:matrix` children are column-major, which the samples confirm.

### 2.4 Cached results (`result.xml`)

```xml
<resultsList xmlns="http://schemas.mathsoft.com/result10" xmlns:ml="..." xmlns:u="...">
  <resultData result-id="7" calculation-status="Synchronized">
    <ml:result>
      <ml:unitedValue>
        <ml:real>1.9200000000000017</ml:real>
        <u:unitMonomial><u:unitReference unit="meter" power-numerator="1" power-denominator="1"/></u:unitMonomial>
      </ml:unitedValue>
    </ml:result>
  </resultData>
```

- Values are stored in SI base units (`meter`, not the `m` or `mm` the user sees). The
  display unit is the `unitOverride` in the worksheet. Rezzer needs a small unit table to
  show `1920 mm`, or it shows the SI value and says so.
- `calculation-status` seen: `Synchronized` (450) and `Pending` (20). `Pending` means the
  sheet was saved without a fresh result; Rezzer must say "not calculated" instead of
  printing a stale or missing number.
- Engine errors are stored with their message text:

```xml
<resultData result-id="0" calculation-status="Synchronized">
  <engineErrors>
    <engineError error-id="0" error-node-handle="3">
      <errorCode>bad%_variable doc_mc_X#wild</errorCode>
      <resource-string>This variable is undefined. Check that the label is set correctly.</resource-string>
    </engineError>
  </engineErrors>
</resultData>
```

- `settings/calculation.xml` has `cache-worksheet="true|false"`. Two samples with `false`
  still had cached values, so the exact meaning is **[unverified]**.
- Matrices, strings and `Warning` elements (redefinition of a built-in, with `nodeId` such
  as `mc_C#VARIABLE`) also appear.

### 2.5 Plots

Plots keep their definition in the worksheet (trace expressions, unit per axis, axis range,
style) and their computed data in `result.xml`:

```xml
<plot><xyPlot><traces><trace resultRef="42"><traceStyle color="#FF00008B" line-style="Solid">lines</traceStyle></trace>...
  <xAxis start="-750" end="750"> ... <plotEquation>
     <math><ml:apply><ml:matcol/><ml:id labels="VARIABLE">Contour</ml:id><ml:real>0</ml:real></ml:apply></math>
     <math><ml:id labels="UNIT">mm</ml:id></math>
  </plotEquation>
```

```xml
<resultData result-id="42" calculation-status="Synchronized">
  <ml:Trace2dResult TraceType="Vector">
    <ml:RangeInfo Min="-650" Max="650"/>
    <ml:Data>
      <ml:RangePoints><ml:DataVectors VectorsType="Columns" Count="1" VectorLength="5" ValuesType="Numeric">[-650,-650,650,650,-650]</ml:DataVectors></ml:RangePoints>
      <ml:ResultPoints><ml:DataVectors ...>[-650,650,650,-650,-650]</ml:DataVectors></ml:ResultPoints>
```

So Rezzer can describe a plot (what is plotted against what, in which units, ranges) and
even output the data points or a Mermaid `xychart-beta`, without rendering. There is no
rendered image of the plot in the file. 3D and contour plots exist (`plot3D`,
`contourPlot` per mcad2py notes) but were not in the samples **[unverified]**.

### 2.6 Text, header, footer, metadata

- A text region in `worksheet.xml` is only a stub (`<text item-idref="R...">` with an empty
  `FlowDocument`). The text is in `mathcad/xaml/FlowDocumentN.XamlPackage`, a nested OPC zip
  with `Xaml/Document.xaml` (WPF `Section`/`Paragraph`/`Run`). Example:
  `<Run style="Normal">Biaxial bending verification of RC column</Run>`. Text can also hold
  inline math (`is-text-block` attribute seen) **[unverified detail]**.
- Header and footer use the same region model. Page-number fields are `<fieldText>` with a
  `<pageNumber template="Page_@PageNo_of_@PagesTotal">` (from mcad2py notes; seen in the
  Prime 12 sample).
- `docProps/core.xml`: creator, last modified by, revision. Often empty. No title or
  subject in the samples.
- `docProps/app.xml`: product version, engine version, build date, culture.

### 2.7 Protection and encryption

- **No encryption** was seen in any sample: every part is plain zip deflate XML. No
  `EncryptionInfo` part as in encrypted Office files. Whole-file encryption is not offered
  by Prime as far as PTC's help shows **[unverified for all versions]**.
- Prime has "protected areas": a collapsible area can be protected against editing, with an
  optional password, and its expand/collapse state can be locked
  ([PTC help r11, Protect or Unprotect an Area](https://support.ptc.com/help/mathcad/r11.0/en/PTC_Mathcad_Help/to_protect_unprotect_an_area.html)).
  PTC's page says nothing about encrypting the content. Password protection came with Prime
  4.0 (community thread) **[unverified]**. No sample with a protected area was found, so how
  it is stored (plain XML plus a password hash, or encrypted) is **[unverified]**.
- Rezzer policy proposal: if a protected area is plain XML, read it and mark it in the output
  as "protected area (locked by author)". If it is encrypted, report it as unreadable with
  the reason. Never try to guess, crack or remove a password, and never offer such a
  feature.

## 3. Mathcad 12-15 `.xmcd` and older `.mcd`

### 3.1 Facts and a correction

- The task said "Mathcad 11-15 `.xmcd`". The sources say XML became the native format with
  **Mathcad 12** (Mathsoft, 2004/2005): "Mathcad 12 adopts XML as its native file format"
  ([Control Engineering](https://www.controleng.com/mathcad-upgrade-incorporates-xml/)).
  Mathcad 11 and older write binary `.mcd`. Mathcad 12-15 can still save `.mcd` **[unverified]**.
- Variants: `.xmcd` (worksheet), `.xmcdz` (compressed), `.xmct` (template)
  ([Medusa format registry](https://medusa.library.illinois.edu/file_formats/121)). No
  `.xmcdz` sample was found; its compression is **[unverified]**.
- Root: `<worksheet version="3.0.3" xmlns="http://schemas.mathsoft.com/worksheet30"
  xmlns:ml="http://schemas.mathsoft.com/math30" xmlns:u="http://schemas.mathsoft.com/units10"
  xmlns:p="http://schemas.mathsoft.com/provenance10">`. All five samples (Mathcad 14.0 and
  14.1) use version 3.0.3.
- A processing instruction `<?validation-md5-digest ...?>` sits before the root. It is a
  checksum, not protection; it matters only to writers.

### 3.2 The XML schema: where it is and its license

- PTC never published the `.xmcd` schema on a website. The XSD files ship **inside the
  Mathcad 15 installation**, in `C:\Program Files (x86)\Mathcad\Mathcad 15\schema`
  (community answer by a poster named Mona in
  [PTC Community: xmcd XML format specification](https://community.ptc.com/discussions-148/xmcd-xml-format-specification-12065);
  also [PTC Community thread on worksheet30.xsd](https://community.ptc.com/t5/PTC-Mathcad/After-upgrading-to-Mathcad-15-M040-I-m-no-longer-able-to-open/td-p/261595),
  where a user validated files against `worksheet30.xsd` together with `math30`, `units10`
  and `provenance10`).
- License: the XSDs are part of the installed "Licensed Products" under the PTC Customer
  Agreement. They carry no open license. No public copy was found on GitHub (code search for
  `worksheet30.xsd`, `math30.xsd` and the `targetNamespace` returned nothing). **Rezzer must
  not copy them, and nobody should read them for Rezzer** (see section 6).
- For Prime there is no shipped XSD known. `scodge-24/mcdx-toolbox` (MIT) has XSDs, but its
  NOTICE says "Schemas are project approximations, not official PTC validation schemas", and
  one XSD has an "Auto-augmented on discovery" note. They are lax hand-made schemas, not a
  spec.

### 3.3 Structure

Math is the same content-math idea as Prime with namespace `math30`, and the **result is
inline** inside `<ml:eval>` (`csamp_Hand_Calculations.xmcd`, Mathcad 14.1):

```xml
<region region-id="130" left="468" top="74.25" ... is-protected="true">
  <math optimize="false" disable-calc="false">
    <ml:define>
      <ml:id xml:space="preserve">Coxn</ml:id>
      <ml:eval>
        <ml:apply><ml:mult/><ml:id>eps0</ml:id><ml:apply><ml:div/><ml:id>epsrox</ml:id><ml:id>ntox</ml:id></ml:apply></ml:apply>
        <ml:unitOverride><ml:apply><ml:div/><ml:id>F</ml:id><ml:apply><ml:pow/><ml:id>m</ml:id><ml:real>2</ml:real></ml:apply></ml:apply></ml:unitOverride>
        <result xmlns="http://schemas.mathsoft.com/math30">
          <unitedValue><ml:real>0.0083247324011571835</ml:real>
            <unitMonomial xmlns="http://schemas.mathsoft.com/units10">
              <unitReference unit="farad"/><unitReference unit="meter" power-numerator="-2"/>
            </unitMonomial></unitedValue>
        </result>
      </ml:eval>
    </ml:define>
  </math>
  <rendering item-idref="8"/>
</region>
```

Differences to Prime that matter:

- `ml:id` has **no `labels` role attribute** in math30. Units and variables look the same
  (`<ml:id>m</ml:id>`), so Rezzer must tell a unit from a variable by context and a unit
  name table. Subscripts are an attribute (`subscript`), not a WPF span.
- Text regions are inline XHTML-like markup (`<text><p style=...>` with `<inlineAttr>`,
  `<b>`, `<i>`, `<sp>`, `<tab>`), not a nested zip. Easier than Prime.
- `<metadata>`: `generator` ("Mathcad Professional 14.1"), `userData` (title, description,
  author, company, keywords, revisedBy), `identityInfo` (revision, documentID, versionID,
  parentVersionID, branchID). Better metadata than Prime.
- **Provenance**: `<ml:provenance>` records where a pasted expression came from, with the
  source document GUID, revision and a local file path:
  `href="D:\Мои Документы\Тепловые поля SLM - рабочий вариант 1.xmcd"`. Good for
  Rezzer's provenance model, but it can leak local paths and user names; flag it.
- Every region has `<rendering item-idref="N"/>`, a PNG of the region as Mathcad drew it,
  stored base64 in `<binaryContent><item item-id="N">`. That gives a ready "needs vision"
  image for anything Rezzer cannot parse.
- **Plots are not XML.** `<plot item-idref="14"/>` points to an item with
  `content-encoding="gzip"` that holds a legacy binary serialization (class names such as
  `eqRegion`, `docRegion`, `mcObject`, `trace2D`, `axisFormat`, `d2_graph_format` and
  UTF-16 strings for axis expressions are visible). Rezzer should not parse this. It should
  extract the region PNG, mark the plot as "needs vision" and list it.
- Areas: `<area is-collapsed="true" is-locked="false" allow-expand="false"
  top-lock-id="126" bottom-lock-id="128">`. `is-protected` on regions is `true` by default
  in four of five samples, so it is not a sign of a password; it relates to worksheet
  protection **[unverified]**. Mathcad 12-15 had worksheet protection with an optional
  password **[unverified]**; `philpem/magick` (no license, code not read) calls itself an "XML-form (.xmcd)
  Mathcad password remover", which suggests the password is checked by the program and the
  content is plain XML **[unverified]**. Same policy as Prime: read, mark as protected,
  never remove.

### 3.4 Binary `.mcd`

- No public specification and no open-source parser was found (GitHub repository and code
  search, web search). The Mathcad Prime Legacy Converter (PTC) converts legacy worksheets
  to `.mcdx`; unsupported content is "annotated, and the original is saved as an image"
  ([PTC help r11, Converting Legacy Worksheets](https://support.ptc.com/help/mathcad/r11.0/en/PTC_Mathcad_Help/converting_legacy_mathcad_worksheets.html)).
  Whether it handles all `.mcd` versions and needs Mathcad 15 installed is **[unverified]**.
- Rezzer: detect `.mcd` (Mathcad, not the many other `.mcd` formats), report "binary
  Mathcad 11 or older worksheet, not readable; convert with PTC's legacy converter", and
  extract nothing it cannot verify. Reverse engineering this binary would be the only way
  and is not worth it (see section 6).

## 4. SMath Studio `.sm`

### 4.1 Facts

- SMath Studio by SMath LLC (Russia). Closed source. Wikipedia lists release 1.5.0.9678
  of 2026-07-01 ([Wikipedia](https://en.wikipedia.org/wiki/SMath_Studio)). Since
  2023-09-11 it is sold under paid "Personal", "Advanced" and "Unlimited" licenses with a
  trial; older versions were free for personal use
  ([SMath terms of use, version of 2023-09-11](https://smath.com/en-US/view/SMathStudio/license)).
- Format documentation: none found. The format is plain XML and easy to read.
- Roadmap: "Mathcad Prime files import" (June 2026) and "Introduction of a new ODF
  compatible files format, ensuring full backward compatibility with existing worksheets"
  for SMath Studio 3.x, planned January 2028
  ([SMath roadmap PDF](https://smath.info/en-US/Roadmap/pdf)). A plan, not a release.

### 4.2 Structure

Root `<regions>` (namespace `http://smath.info/schemas/worksheet/1.0` from 0.98, none in
0.97), preceded by `<?application progid="SMath Studio Desktop" version="0.98.6398.26177"?>`.
`<settings>` has identity (GUID, revision), calculation (precision, fractions), page model,
header/footer templates and a `<dependencies>` list of plugin assemblies with GUIDs.

Expressions are **postfix token lists**, not trees. Units are tagged with `style="unit"`.
`:` is the definition operator. A cached result has its own display unit (`<contract>`)
(`calculix_Beam.sm`, SMath 0.98):

```xml
<region id="9" left="234" top="153" width="91" height="24">
  <math><input>
    <e type="operand">E</e>
    <e type="operand">210</e>
    <e type="operand" style="unit">GPa</e>
    <e type="operator" args="2">*</e>
    <e type="operator" args="2">:</e>
  </input></math>
</region>
<region id="10" left="585" top="162" width="131" height="51">
  <math>
    <input><e type="operand">E</e></input>
    <contract><e type="operand" style="unit">N</e><e type="operand" style="unit">mm</e>
              <e type="operand">2</e><e type="operator" args="2">^</e><e type="operator" args="2">/</e></contract>
    <result action="numeric"><e type="operand">2.1</e><e type="operand">10</e><e type="operand">5</e>
              <e type="operator" args="2">^</e><e type="operator" args="2">*</e></result>
  </math>
</region>
```

- Results are cached in the display unit already (here `2.1*10^5 N/mm^2`), unlike Prime.
- Text: `<text lang="eng"><p bold="true">...</p></text>`. Pictures: `<picture><raw
  format="png" encoding="base64">`. Plot and other regions come from plugins (listed in
  `<dependencies>`); none in the samples, so their XML is **[unverified]**.
- Rebuilding an infix tree from postfix needs the arity (`args`), which is in the file. The
  set of operator and function names must be collected from samples.
- No protection or encryption was seen. SMath has no password feature that I know of
  **[unverified]**.

## 6. Legal assessment (not legal advice)

### 6.1 PTC agreement

The current PTC Clickwrap Customer Agreement (Rev. May 2026, linked from
[PTC On-Premises Terms](https://www.ptc.com/en/documents/legal-agreements/on-premise-license-agreements);
the same clause is in Rev. 1/13) says in section 1.4(iv) that the customer shall not:

> disassemble, decompile or reverse engineer the Licensed Products or the file format of the
> Licensed Products, or otherwise attempt to gain access to the source code or file format of
> the Licensed Products, except as expressly permitted in Schedule A, if applicable;

Schedule A, for Austria, Germany and Switzerland:

> Section 1.4 (iv) above shall not apply to the extent that (i) the processes Customer
> undertakes are required to achieve information necessary to achieve interoperability of an
> independently created computer program with other software programs, (ii) the further
> requirements of Section 69e of the German Copyright Act are fulfilled and (iii) PTC, upon
> Customer's written request, has not made available the information required for this
> within a reasonable period.

Points:

- The quoted text is PTC's general on-premises agreement. Whether Mathcad Express or the
  student edition ship with different terms is **[unverified]**.
- A contract binds only its parties, that is people and companies who installed or use PTC
  software. Rezzer's authors do not need Mathcad, and a Rezzer user who has never accepted
  the agreement is not bound by it.
- The clause is unusually explicit: it names "the file format". A Rezzer contributor who
  holds a Mathcad license and studies the format (for example by saving test files and
  diffing them) acts against the contract in the US and other non-EU countries. In DACH the
  Schedule A carve-out applies, and in the EU the mandatory exceptions below apply.
- Parsing XML that a user hands to Rezzer is not "disassembling or decompiling the Licensed
  Products". It touches no PTC code.

### 6.2 EU law

- Directive 2009/24/EC, Art. 5(3): a person with a right to use a program may "observe,
  study or test the functioning of the program in order to determine the ideas and
  principles which underlie any element of the program" while loading, running or storing
  it. Art. 6 allows decompilation of code where indispensable for interoperability of an
  independently created program, under conditions (licensee, information not readily
  available, confined to the needed parts, no other use). Art. 8: "Any contractual
  provisions contrary to Article 6 or to the exceptions provided for in Article 5(2) and (3)
  shall be null and void." (Text read via
  [legislation.gov.uk, Directive 2009/24/EC](https://www.legislation.gov.uk/eudr/2009/24/contents),
  articles 5, 6, 8.) Germany: sections 69d(3) and 69e UrhG.
- CJEU C-406/10 *SAS Institute v World Programming*, 2 May 2012
  ([EUR-Lex 62010CJ0406](https://eur-lex.europa.eu/legal-content/EN/TXT/HTML/?uri=CELEX:62010CJ0406)):
  - Para. 39 and ruling 1: "neither the functionality of a computer program nor the
    programming language and the format of data files used in a computer program in order
    to exploit certain of its functions constitute a form of expression of that program"
    and are not protected by copyright in computer programs.
  - Para. 43: if someone procured "the part of the source code or the object code relating
    to ... the format of data files" and built similar elements with it, that could be
    partial reproduction. So: learn the format from data files, not from vendor code.
  - Para. 45: a data file format might still be protected as a work under Directive
    2001/29 if it is the author's own intellectual creation. This is a residual risk for
    copying a vendor schema text (the XSDs), not for reading files.
  - Paras. 59-62 and ruling 2: a licensee may study the program's behaviour within the acts
    the license allows; a license cannot forbid this (Art. 5(3) with Art. 8/9).
- Art. 6 is about decompiling program code. Rezzer does not need it: the format can be
  learned entirely from public sample files. That is the cleanest position.

### 6.3 What this means for Rezzer

- Reading `.mcdx`, `.xmcd` and `.sm` files is lawful in the EU: the format is not protected
  as program expression (SAS v WPL), and Rezzer uses no vendor code.
- Learn the format **only from public sample files** with a redistributable license (like
  this corpus), plus MIT-licensed descriptions. Do not use PTC software, its installed XSDs,
  its DLLs or decompiled code to learn the format. Do not copy PTC XSD text into the repo.
- If a contributor owns a Mathcad license and wants to create probe files: in the EU this is
  covered by Art. 5(3) and cannot be forbidden by contract; outside the EU it breaches
  section 1.4(iv). Simplest rule: Rezzer contributors do not produce probe files with a
  licensed Mathcad; corpus files come from public sources only.
- SMath terms (Russian law) forbid "decompile, disassemble, decrypt and perform other
  activities with the Software, which are aimed at obtaining information about the
  implementation of the algorithms used in the Software" (clause 4.10.3). They do not
  mention the file format. Reading `.sm` files does not touch SMath's software.
- Trademarks: "Mathcad", "Mathcad Prime" (PTC) and "SMath Studio" may be used only to say
  which formats Rezzer reads. No logos, no suggestion of endorsement.
- No feature that removes, bypasses or guesses worksheet or area passwords. A protected area
  is reported as protected; encrypted content is reported as unreadable.

## 9. What Rezzer could extract

Into Rezzer's document model, then OKF Markdown and Mermaid:

- **Definitions table**: name (with subscript flattened), kind (variable, function with
  parameters, global definition, range, matrix, program), expression as readable infix text
  (and LaTeX if wanted), input or result, cached value with unit, status (current, pending,
  error with message), position (page, top, left), protected or not.
- **Inputs vs results**: a definition whose right side has no identifiers except units and
  constants is an input (`w_c := 1.3 m`). One that references other variables is derived.
  An `ml:eval` or SMath `result` is a shown result. This classification is deterministic from
  the tree.
- **Dependency graph** as Mermaid `flowchart`: edges from each identifier used to the
  definition it resolves to. Pitfall: Mathcad evaluates in reading order (top to bottom,
  then left to right) and allows redefinition, plus global definitions (`≡`) that apply
  everywhere. The graph must resolve each use to the nearest earlier definition by position,
  not by name. Same for SMath. Local definitions inside programs (`ml:localDefine`) are
  scoped to the program.
- **Units**: per value, the unit monomial; the display unit from the override. For Prime,
  results are SI base units; Rezzer needs a unit table (Mathcad's built-in units are a known set;
  user-defined units are themselves definitions in the sheet) to convert to the display unit, or it prints SI and says so.
- **Text** regions in order, with their position, so a value can be tied to the text label
  next to it ("Young's modulus" next to `E := 210 GPa`). Headers and footers separately.
- **Plots**: Prime: what is plotted (trace expressions, axis units, ranges) and the cached
  data vectors, as a data table or Mermaid `xychart-beta`. `.xmcd`: the region PNG, marked as
  "needs vision"; the binary plot blob is not parsed.
- **Solve blocks**: guess values, constraints and the solver call, as a structured block.
- **Pictures**: extracted to files, marked in the text, listed as needing vision.
- **Metadata**: product and version, build date, culture, creator, revision (Prime);
  author, company, title, keywords, document GUIDs (xmcd); SMath version and plugins.
- **Provenance** (xmcd): source document and path of pasted regions, flagged as possibly
  sensitive.
- **Gaps said in the output**: `.mcd` binary, xmcd plot internals, encrypted content,
  plugin regions Rezzer does not know, scripted controls, Excel components, DLL user
  functions (names known, bodies not), file read functions (`READPRN` and similar: the
  external file is not in the worksheet).

Safety: `.mcdx` has zips inside the zip (XamlPackage). Apply the same zip-bomb limits
(entry count, total and per-entry uncompressed size, ratio, depth) as for Office files.
Never evaluate anything: worksheets can call DLL functions and write files when Mathcad
calculates them.

| Format | Verdict | Effort | Notes |
|---|---|---|---|
| `.mcdx` (Prime 3-12) | **Feasible. Do it** | 3-4 weeks for one developer with the corpus: OPC reading (reuse the Office zip code), math50 tree to Rezzer expression model, result join, unit table, XAML text, plots, dependency graph | Stable namespaces since 2013 lower the risk. No crate exists for any of these. Readers are plain `quick-xml` plus `zip` work behind
Rezzer's own format trait, so no license problem. Clean-room process for Rezzer: one agent
writes a facts-only format spec from the public sample files and the MIT notes (mcad2py,
mcdx-toolbox); a different agent implements it from that spec. Nobody involved reads the GPL
or unlicensed projects in section 7.2 or any PTC or SMath software.

Open questions to settle with real files: how a password protected Prime area is stored;
the meaning of `cache-worksheet`; `.xmcdz`; Prime 1-2; SMath plot and plugin regions.
