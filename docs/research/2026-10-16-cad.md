# Rezzer research: engineering, CAD and 3D formats

Date: 2026-10-16. Scope: what an MCP server written in Rust can turn into useful Markdown for AI agents, per format, and with which libraries.

Method: crate versions, dates, licenses and download counts come from the crates.io API (queried 2026-10-16). Stars and push dates come from the GitHub API. Python versions come from the PyPI JSON API. Feature claims come from the project READMEs. **No crate was run on real files.** Claims marked **[unverified]** come from READMEs, self-reported support levels or my own knowledge of the format and were not tested.

## 1. Executive summary

Three tiers:

| Tier | Formats | Approach |
|---|---|---|
| A. Text, zip or XML parsing is enough (pure Rust) | DXF, 3MF (incl. Bambu/Orca/Prusa), STL, OBJ, glTF, SVG, G-code, Gerber, KiCad, OpenSCAD, FreeCAD .FCStd, STEP, IFC, IGES | Read the structure and summarize it. No geometry kernel needed |
| B. Kernel only for exact geometry numbers | STEP, IGES (exact bbox, volume, mass, surface area of B-rep) | Skip the kernel. Approximate bbox from min/max over points and control points (conservative, can be too large). Optional OCCT subprocess for exact numbers |
| C. Closed native binary | DWG (reverse-engineered, now readable), SolidWorks .sldprt/.sldasm, Creo/Pro-E .prt/.asm, Fusion 360 .f3d, NX .prt, CATIA, Inventor | DWG: pure-Rust readers exist (young). Fusion: zip, partly readable. SolidWorks/Creo: metadata, thumbnail and "please export STEP" at best |

Key observations:

- **STEP and IFC share one syntax** (ISO 10303-21 "Part 21"). One generic Part 21 entity reader in Rust gives product tree, BOM, units, names, property sets, materials and PMI text for both. `stepq` (Rust, MIT) shows that this works without a kernel.
- **A wave of new clean-room Rust crates appeared in 2026** (acadrust, cadkit, cadmpeg, stepq, step-io, ifc-lite, lib3mf-core, parasolid-core, rvt). Most are weeks or months old with small download counts. They are promising but must be treated as unproven. The established crates (dxf, stl_io, tobj, gltf, usvg, quick-xml, zip) are solid.
- **Licensing hot spots:** LibreDWG is GPL-3. OpenCascade (OCCT) is LGPL-2.1 with an exception. Several small Rust crates are GPL-3 or AGPL-3 (listed in section 4). The permissive alternatives are good enough for every format.
- **Subprocess fallback tier:** running a GPL or LGPL program as a separate process (LibreDWG `dwg2dxf`, `kicad-cli`, `openscad`, FreeCAD headless `freecadcmd`, ODA File Converter) does not put Rezzer under the GPL. This can be an optional "if installed" path, separate from linked crates.

## 2. Per-format findings

Legend for feasibility: **High** = pure Rust, good text output, low effort. **Medium** = pure Rust possible but needs own work or young crates. **Low** = only metadata or partial data. **Infeasible** = nothing useful beyond file properties without a vendor SDK.

### 2.1 DXF (AutoCAD Drawing Exchange Format)

- **What an agent gets:** header variables ($INSUNITS units, $ACADVER version, $EXTMIN/$EXTMAX drawing extents = bounding box), layers (name, color, on/off, frozen), blocks and block references (INSERT with attributes = title block fields, part numbers, a BOM-like list), TEXT/MTEXT content, DIMENSION entities (measured value and override text), layouts/paper space, entity counts per layer and type, XDATA app names.
- **Rust crates:**
  - `dxf` 0.6.2 (2026-10-03), MIT, 309k downloads, ixmilia/dxf-rs 142 stars. Pure Rust, ASCII and binary DXF, R10 to R2018. Mature, the safe choice.
  - `acadrust` 0.6.4 (2026-10-11), MPL-2.0, 36k downloads, 125 stars, first release 2026-02. Pure Rust. DXF and DWG R12 to R2018+, 48 entity types, dimensions, dynamic blocks, ACIS SAT/SAB, failsafe reading with diagnostics, optional serde. **[unverified fidelity]**
  - `cadkit` 0.3.1 (2026-10-16), MIT OR Apache-2.0, first release 2026-10-01, 3 stars. DXF, DWG, DGN V7/V8, CityGML into one neutral model. Very young.
- **Non-Rust best:** Python `ezdxf` 1.4.5 (2026-10-16), MIT, 1.5k stars. The reference for DXF; good for cross-checking output.
- **Recommendation:** pure Rust. Start with `dxf` (MIT, mature). Consider `acadrust` if DWG support is wanted from the same model (one crate for both). Output: header table, layer table, block list with attribute values, all text and dimension strings grouped by layer/layout.
- **Feasibility: High.**

### 2.2 DWG (AutoCAD native, closed binary)

- **What an agent gets:** the same as DXF when the reader works.
- **Options:**
  - **LibreDWG** (C, GPL-3.0, 1.6k stars, active). Rust bindings `libredwg-sys` 0.12.0 (2026-10-07, GPL-3.0-or-later) and `uncad` 0.12.0 (GPL-3.0-or-later). **Linking makes Rezzer GPL-3.** Usable only as a subprocess (`dwg2dxf`, `dwgread`) if the user has it installed.
  - `acadrust` (MPL-2.0, pure Rust): claims DWG read and write R12 to R2018+ (R12 DWG incomplete). **[unverified on real files]**
  - `cadkit` / `cadkit-dwg` (MIT OR Apache-2.0, pure Rust, clean-room): DWG read AC1014 (R14) to AC1032 (2018), no writer, "entity coverage is still growing". First release 2026-10-01. **[unverified]**
  - `dwg2geo` 0.2.5 (MIT): DWG to GeoJSON; niche.
  - **ODA File Converter** (Open Design Alliance, freeware, proprietary, closed): converts DWG to DXF as an external program. Free to download but not open source; cannot be bundled freely. ODA SDK (Teigha) itself is commercial and needs a membership.
- **MPL-2.0 note:** MPL-2.0 is file-level copyleft. Linking an MPL crate from an MIT/Apache project is fine; only changes to the MPL files themselves must be shared.
- **Recommendation:** use `acadrust` (or `cadkit`) for DWG behind a feature flag, with a robust fallback: if parsing fails, report version (the first 6 bytes, e.g. `AC1032`), embedded thumbnail and file properties. Optional subprocess to `dwg2dxf` or ODA File Converter if found on PATH. Build a test corpus before trusting any of the pure-Rust readers.
- **Feasibility: Medium** (was Low two years ago; depends on how good the new pure-Rust readers really are).

### 2.3 3MF (incl. Bambu Studio, OrcaSlicer, PrusaSlicer)

- **Structure:** OPC zip. `3D/3dmodel.model` (XML: units, metadata like Title/Designer/Application, objects, components, build items with transforms, base materials, color groups), `[Content_Types].xml`, `_rels`. Extensions: production (multi-file), materials, beam lattice, slice.
  - **Bambu Studio / OrcaSlicer:** `Metadata/project_settings.config` (JSON, full print profile: printer, layer height, infill, supports, filament types), `Metadata/model_settings.config` (XML: per-object and per-plate settings, part names), `Metadata/slice_info.config` (XML: print time, filament weight per plate, warnings), `Metadata/plate_N.png` thumbnails, and in sliced exports `Metadata/plate_N.gcode`. Verified via a Bambu forum listing and the `lib3mf-core` docs.
  - **PrusaSlicer:** `Metadata/Slic3r_PE.config` (INI-style print, filament and printer settings) and `Metadata/Slic3r_PE_model.config` (per-object/volume settings, extruder assignment). Verified via two independent web sources.
- **What an agent gets:** object/part names and counts, units, triangle counts per object, bounding box (computed from vertices, cheap), plates, assigned filaments/materials and colors, all print settings, estimated print time and filament usage.
- **Rust crates:**
  - `threemf` 0.8.0 (2026-03-05), 0BSD, 46k downloads, from the Fornjot project. Core spec only, "functionality is limited".
  - `lib3mf-core` 0.4.0 (2026-03-04), BSD-2-Clause, 1.3k downloads, 12 stars. Pure Rust, streaming parser, validation, and **Bambu config parsers** (`parser::bambu_config`: slice_info, model_settings, project_settings).
  - `lib3mf` 0.1.6 (2026-03-13), MIT, pure Rust (different project, telecos/lib3mf_rust).
  - `threemf2` 0.4.1 (2026-08-17), MIT or Apache-2.0, small.
  - Official C++ **lib3mf** (3MF Consortium), BSD-2-Clause, 314 stars; Python `lib3mf` 2.5.0 (2026-02-23). Needs C++ toolchain/FFI.
- **Recommendation:** pure Rust with `zip` 9.0.4 (MIT) + `quick-xml` 0.42.0 (MIT) + `serde_json`, or `lib3mf-core` for the model and Bambu configs. Handle Prusa INI and Bambu JSON yourself (simple). Output: metadata table, object table with bbox and triangle count, plate table, print-settings table (filtered to the 20 to 40 most important keys, full list in a collapsible section).
- **Feasibility: High.**

### 2.4 STL

- **What an agent gets:** ASCII or binary, solid name (ASCII) or 80-byte header text (binary, often contains the exporting program), triangle count, bounding box, size in each axis, surface area, volume (signed tetrahedron sum, valid for closed meshes), watertight/manifold check (edge counting), units are **not** stored (usually mm, say so). Multi-solid ASCII files list each solid.
- **Rust crates:** `stl_io` 0.11.0 (2026-03-15), MIT, 5.1M downloads. Mature. Alternatives: `nom_stl` (MIT, old), `cvkg-stl` (**EPL-2.0**, avoid for simplicity).
- **Non-Rust:** Python `numpy-stl` 4.0.1 (BSD-3), `trimesh` 5.1.1 (MIT).
- **Recommendation:** pure Rust `stl_io`; compute stats directly. No kernel needed.
- **Feasibility: High** (but low information content: geometry only).

### 2.5 OBJ (Wavefront) + MTL

- **What an agent gets:** object (`o`) and group (`g`) names, material names and MTL properties (colors, texture file names), vertex/face counts, bbox, comments (often the exporter name).
- **Rust crates:** `tobj` 4.0.5 (2026-08-02), MIT, 3M downloads. `obj-rs` 0.7.4 (2024-09), MIT OR Apache-2.0. `obj` 0.10.2 (2020, stale).
- **Recommendation:** pure Rust `tobj`. Also keep `#` comments (export program, units hints).
- **Feasibility: High.**

### 2.6 glTF / GLB

- **What an agent gets:** asset generator and version, extensions used, scene graph (nodes, hierarchy, names, transforms), meshes with primitive counts and accessor min/max (bbox is stored in the file for positions), materials (PBR values, texture names), animations, skins, cameras, `extras` user data. The node tree maps well to a Mermaid graph.
- **Rust crates:** `gltf` 1.4.1 (2024-05-10), MIT OR Apache-2.0, 10.5M downloads, 644 stars (repo pushed 2026-05). Mature, though no release since 2024. `gltf-json` for JSON only. `easy-gltf` 1.1.5 (MIT).
- **Recommendation:** pure Rust `gltf` (or just `gltf-json` + GLB chunk split, no buffer decoding needed for a summary).
- **Feasibility: High.**

### 2.7 SVG

- **What an agent gets:** title/desc, viewBox and width/height (with units), text content (`<text>`, `<tspan>`), element ids and classes, groups/layers (Inkscape `inkscape:label` and `inkscape:groupmode="layer"`), embedded metadata (RDF), linked images. For diagrams, text labels plus group structure are often enough to rebuild a rough Mermaid diagram, but this is heuristic.
- **Rust crates:** `usvg` / `resvg` 0.48.1 (2026-08-02), Apache-2.0 OR MIT, 30M+ downloads (linebender). `usvg` normalizes the tree (useful for bbox), but for text extraction `quick-xml` or `roxmltree` is enough and safer.
- **Recommendation:** pure Rust XML walk (`roxmltree` / `quick-xml`); `usvg` only if bboxes or rendering to PNG for a vision model are wanted.
- **Feasibility: High.**

### 2.8 STEP (ISO 10303-21; AP203, AP214, AP242)

- **Structure:** ASCII Part 21 file: HEADER (FILE_DESCRIPTION, FILE_NAME with author, organization, originating system, timestamp; FILE_SCHEMA = which AP) and DATA (numbered entities `#123=ENTITY(...)`).
- **What an agent gets without a kernel:** schema/AP, originating CAD system, author, date; units (length unit + conversion, e.g. inch); **product structure** (PRODUCT, PRODUCT_DEFINITION, NEXT_ASSEMBLY_USAGE_OCCURRENCE = assembly tree and BOM with quantities, placements); part names and IDs; colors and layers (presentation entities); user properties; materials (if exported); **AP242 PMI** (GD&T tolerances, datums, dimensions, often semantic, sometimes only graphic polylines); solid counts, face counts, surface type histogram; approximate bbox from CARTESIAN_POINT min/max (conservative: NURBS control points can lie outside the true shape).
- **What needs a kernel:** exact bbox, volume, mass, surface area, center of gravity, tessellation for rendering.
- **Rust crates:**
  - `stepq` 0.6.0 (2026-10-11), MIT, 1 star, first release 2026-09-13. Pure Rust, no kernel. `info`, `tree`, `bom`, `props`, `pmi` (semantic GD&T), `diff`, `lint`. Matches Rezzer's needs very closely. Early, API unstable. **[unverified]**
  - `step-io` 0.2.5 (2026-10-03), MIT OR Apache-2.0, "experimental". Reads all mainstream APs into one schema model, writes AP242.
  - `step-p21` 0.1.1 (2026-08-18), Apache-2.0: generic Part 21 parser with serde entity tables.
  - `cadmpeg-codec-step` 0.6.1 (2026-10-12), Apache-2.0: read/write AP203/214/242, self-rated L9. **[unverified]**
  - `ruststep` 0.4.0 + `truck-stepio` 0.3.0 (both 2024-09-20), Apache-2.0. Crate releases stale since 2024-09, although the truck repo (1.6k stars) is still active. truck is a pure-Rust B-rep kernel and can tessellate STEP (limited robustness on real files **[unverified]**).
  - `iso-10303` 0.5.0 (2021), MIT: stale.
  - Kernel bindings: `opencascade` / `opencascade-sys` 0.3.0 (2026-08-24), **LGPL-2.1** (OCCT). `cadrum` 0.9.0 (2026-10-10) is labelled MIT, but it **statically links OCCT, which stays LGPL-2.1 (with OCCT exception)**: a static link into a Rust binary brings LGPL relinking obligations (ship object files or allow relinking). The MIT label of the wrapper does not change that.
- **Non-Rust:** OCCT 7.x/8.x C++ (LGPL-2.1 + exception, 3k stars); Python `cadquery-ocp` 8.0.1.1.0 (2026-10-05; wrapper Apache-2.0, bundled OCCT LGPL), `build123d` 0.13.0 (Apache-2.0), `cadquery` 2.8.0. FreeCAD headless (LGPL-2.1). Commercial: ODA, CAD Exchanger, Datakit.
- **Recommendation:** write (or adopt) a small generic Part 21 tokenizer + reference graph in Rust (a few hundred lines) and build the product tree/BOM/units/properties/PMI extraction on top; evaluate `stepq` as library first. Assembly tree and BOM map naturally to a Mermaid graph plus a Markdown BOM table. Exact mass/volume: optional subprocess (FreeCAD/cadquery script) if installed, not linked.
- **Feasibility: High** for structure and metadata; **Medium/kernel** for exact geometry.

### 2.9 IGES

- **Structure:** fixed 80-column ASCII with sections S (start, free text), G (global: sender, file name, originating system, **units flag and name**, model scale, date, author, organization, max coordinate), D (directory: entity type per entity), P (parameter data), T (terminate). Also a rare compressed ASCII variant.
- **What an agent gets:** start section text, all global fields, entity-type histogram (e.g. 128 B-spline surface, 144 trimmed surface, 186 solid), names (entity 406 form 15), levels/layers, general notes (entity 212, contains annotation text), drawings/views (404/410), approx bbox from points.
- **Rust crates:** `cadmpeg-codec-iges` 0.6.1 (Apache-2.0, self-rated L9 **[unverified]**), `ogeom-io` 0.11.2 (MIT OR Apache-2.0, young), `monstertruck-io` 0.4.1 (Apache-2.0), `brepkit-io` 4.2.2 (**AGPL-3.0-only**, avoid).
- **Recommendation:** hand-written reader for S/G/D sections is simple (fixed columns) and covers the useful text. Kernel only for exact geometry.
- **Feasibility: High** for metadata; geometry low value.

### 2.10 FreeCAD .FCStd

- **Structure:** zip with `Document.xml` (all objects, their types such as `PartDesign::Pad`, `Sketcher::SketchObject`, `Spreadsheet::Sheet`, properties incl. `Length`, `Placement`, `Label`, `ExpressionEngine` expressions, links between objects = feature tree / dependency DAG, sketch geometry and constraints with values), `GuiDocument.xml` (visibility, colors), `.brp` files (OCCT BREP of each shape), `thumbnails/Thumbnail.png`.
- **What an agent gets:** **the full parametric feature tree** with parameters, sketches with constraint lists and dimension values, spreadsheet cells (often the design parameters), assembly links, TechDraw pages, document metadata (author, company, license, created/modified). Feature DAG maps well to Mermaid.
- **Rust crates:** `cadmpeg-codec-freecad` 0.6.1 (Apache-2.0, self-rated L5 "shape complete"; sketches, constraints, design operations, TechDraw **[unverified]**). FerroCAD crates (2026-10, experimental FreeCAD reimplementation) are not relevant.
- **Non-Rust:** FreeCAD itself headless (`freecadcmd`, LGPL-2.1, 34k stars) as subprocess for exact volume/bbox via its Python API.
- **Recommendation:** pure Rust `zip` + `quick-xml`; own mapping of the most common object types (PartDesign Body/Pad/Pocket/Fillet/Chamfer/Hole, Sketcher constraints, Spreadsheet, Part primitives, Assembly). Optionally use `cadmpeg-codec-freecad`. `.brp` geometry can be ignored for text output.
- **Feasibility: High.** One of the richest sources for agents.

### 2.11 PTC Creo / Pro/ENGINEER .prt / .asm (also .prt.1, .prt.2 versioned names)

- **Structure:** proprietary binary/text mix. Files start with a `#UGC:2` header line per cadmpeg docs; sections, Unix-compress payloads, PSB-encoded data, Granite kernel data. Also contain a text area with model info in some versions **[unverified]**.
- **Extension collision:** `.prt` is also Siemens NX (and older Unigraphics) and Solid Edge uses `.par`. **Detect by magic bytes, not by extension** (`#UGC:` for Creo; NX `.prt` is an OLE/CFB container with Parasolid inside).
- **Rust:** `cadmpeg` (Apache-2.0, clean-room) rates Creo at **L1 "opened"**: sections, versions, parameter dictionaries (`double_xar` scalar parameters with values), partial planes/cylinders/sketches as extras. **[unverified]**
- **Commercial:** Creo Toolkit / Creo Object Toolkit (needs Creo license), ODA does not cover Creo; CAD Exchanger and Datakit are commercial.
- **Recommendation:** detect, report version, file name, embedded parameter names/values where cadmpeg can read them, and tell the agent to ask for a neutral export: **STEP AP242** (best: assembly + PMI), or IGES/STL/3MF; for drawings, PDF or DXF.
- **Feasibility: Low** (metadata only), geometry/features effectively **Infeasible** today.

### 2.12 SolidWorks .sldprt / .sldasm / .slddrw

- **Structure:** before ~SW2015 an OLE Compound File (CFB); newer versions a proprietary container. Contains Parasolid streams (geometry), preview bitmap, custom properties (Description, Material, PartNo, Author, often the BOM data), configurations.
- **Rust:** `cadmpeg-codec-sldprt` 0.6.1 (Apache-2.0) at **L1**: CRC-framed blocks, Parasolid partitions, partial geometry and topology. `parasolid-core` 0.3.7 (MIT AND Apache-2.0, 2026-10) parses Parasolid X_T/X_B. **[unverified]**
- **Vendor:** SolidWorks Document Manager API (Windows only, needs a license key) reads custom properties, configurations, references and preview without SolidWorks. eDrawings: viewer only.
- **Recommendation:** detect; extract what the container exposes (preview PNG, custom properties if found as text, configuration names); for older CFB files, `cfb` crate (MIT) can read the OLE streams. Ask for STEP AP242 or Parasolid X_T export.
- **Feasibility: Low** (metadata), features **Infeasible**.

### 2.13 Autodesk Fusion 360 .f3d / .f3z

- **Structure:** zip archive with manifests, Protein material assets, ASM (ACIS-derived) `.smb`/`.smbh` geometry blobs, design/history records.
- **Rust:** `cadmpeg` rates f3d at **L4 "design records"** (geometry plus features with operation semantics such as extrude profile/direction/extent, sketch geometry). This is a notable exception among native formats. **[unverified]**
- **Recommendation:** zip listing + manifest metadata in pure Rust always; optional feature-tree extraction via `cadmpeg` codec crates if they hold up on a test corpus. Otherwise ask for STEP export.
- **Feasibility: Medium** (metadata High, features depend on cadmpeg).

### 2.14 OpenSCAD .scad

- **What an agent gets:** it is source code, so the text is already readable. Useful additions: list of modules and functions with parameters, top-level variables (often Customizer parameters with comments like `// [10:100]`), `include`/`use` dependencies, call tree (Mermaid), and optionally a bbox / STL via the OpenSCAD CLI.
- **Rust:** `tree-sitter-openscad-ng` 0.7.1 (2026-03-21), **MIT**, official openscad org. `openscad-rs` 0.1.0 is **GPL-3.0** (avoid). `openscad-lsp` 2.0.2 (MIT OR Apache-2.0) as reference.
- **External:** `openscad` CLI (GPL-2) as subprocess to export STL/3MF and then reuse the STL summary.
- **Recommendation:** return the source as a code block plus a tree-sitter-based outline. **Feasibility: High.**

### 2.15 KiCad (.kicad_sch, .kicad_pcb, .kicad_pro, .kicad_sym, .kicad_mod)

- **Structure:** KiCad 6+ files are s-expressions; `.kicad_pro` is JSON. KiCad 5 schematics (`.sch`) use an older line-based format (legacy).
- **What an agent gets:** schematic: title block, sheets hierarchy (Mermaid), symbols with reference, value, footprint, datasheet, custom fields (**BOM**), nets via labels, text notes. PCB: board outline size (bbox from Edge.Cuts), layer stack, footprints with reference/value/position/side, net list, track/via counts, design rules, zones.
- **Rust crates:** no mature permissive KiCad crate:
  - `kicad-parser` 0.0.10 is **GPL-3.0-or-later** (avoid).
  - `kicad_parse_gen` 7.0.2 (2018, MIT/Apache) supports only old formats, stale.
  - `serde_kicad_sexpr` 0.1.0 (2022, Apache-2.0 OR LGPL-3.0), stale.
  - `kicad-ipc-rs` (MIT) / `kicad-api-rs` (GPL-3) talk to a running KiCad, not useful.
  - Generic s-expression: `lexpr` 0.2.7 (MIT OR Apache-2.0) or a ~150-line hand-written reader.
- **Non-Rust:** `kicad-cli` (ships with KiCad, GPL-3) can export BOM, netlist, PDF/SVG as subprocess. Python `kiutils` 1.4.8 (**GPL-3**, stale since 2024), `kicad-sch-api` 0.5.6 (MIT), `kicad-skip`.
- **Recommendation:** own s-expression reader + extraction for the listed items. **Feasibility: High.**

### 2.16 Gerber (RS-274X, Gerber X2/X3) and Excellon drill

- **What an agent gets:** with X2 attributes: `%TF.FileFunction` (Copper,L1,Top / Soldermask / Legend / Profile), `%TF.GenerationSoftware`, `%TF.CreationDate`, `%TF.ProjectId`, part type; X3 adds component data (`%TO.C` reference designators). Always: units (`%MO`), format, aperture list, object counts, bbox (board size from profile layer), drill sizes and counts from Excellon.
- **Rust crates:** `gerber_parser` 0.5.0 (2026-05-20) + `gerber-types` 0.7.0, MIT OR Apache-2.0 (MakerPnP). `gerberx2` 0.1.2 (2026-05-18), MIT OR Apache-2.0 (diodeinc). `lib_gerber_edit` (non-standard license, avoid). `gerber_viewer` / `gerber2svg` for rendering.
- **Non-Rust:** Python `gerbonara` 1.6.3 (Apache-2.0), `pygerber` 2.4.3 (MIT).
- **Recommendation:** pure Rust, `gerber_parser`; for a zip of Gerbers, give a per-layer table. **Feasibility: High** (summary), visuals need rendering.

### 2.17 G-code

- **What an agent gets:** the most useful data is in **comments**: slicer name/version, estimated time, filament length/weight, layer count, and the full settings block (PrusaSlicer/Bambu/Orca/Cura append all settings as `; key = value` at the end; Cura uses `;SETTING_3` and header `;FLAVOR`, `;TIME`). Also embedded thumbnails (base64 PNG/QOI between `; thumbnail begin`/`end`). From commands: bbox of moves, max Z, number of layers, temperatures (M104/M140), tool changes, units (G20/G21), absolute/relative. CNC G-code: tools (T), spindle speeds, feed rates, work offsets, program comments.
- **Rust crates:** `gcode` 0.7.0 (2026-04-02), MIT OR Apache-2.0, no_std parser. `g-code` 0.6.0 (2026-03-04), MIT OR Apache-2.0. `gcode-nom` 0.7.0 (MIT). `chipbreaker-gcode` is **GPL-3** (avoid). `gcode-thumb` 1.0.1 extracts thumbnails.
- **Recommendation:** streaming line reader (files are often 10 to 200 MB): read header and footer comments fully, sample/aggregate the body. A hand-written reader is enough. **Feasibility: High.**

### 2.18 IFC (BIM; ISO 16739)

- **Structure:** mostly Part 21 (same as STEP) with IFC2X3/IFC4/IFC4X3 schema; also ifcXML, ifcZIP and the new IFC5/IFCX (JSON).
- **What an agent gets:** project, site, building, storeys, spaces (spatial tree, Mermaid), element counts by type (walls, doors, windows, slabs), names/GUIDs, property sets (Pset_*), quantity sets (areas, volumes, if exported), materials and layer sets, classifications, units, author/application from header.
- **Rust crates:**
  - `ifc-lite-core` 20.4.0 (2026-10-11), **MPL-2.0**, 23k downloads, 426 stars, LTplus-AG. IFC2X3, IFC4/4X3, IFC5. Very active (94 versions since 2026-01). Geometry crates `ifc-lite-geometry` etc. Best candidate.
  - `oxideav-ifc` 0.0.3 (MIT), clean-room, very young.
  - `ifc_rs` 0.1.0-alpha.9 (2024-12, MIT), stale.
  - `openbim-ifc-cli` 0.3.0 is **AGPL-3.0** (avoid).
  - `rvt` 0.4.0 (Apache-2.0, 2026-09): clean-room Revit .rvt/.rfa metadata reader, bonus. **[unverified]**
- **Non-Rust:** IfcOpenShell 0.9.0.post1 (2026-10-15), **LGPL-3.0**, 2.9k stars: the reference; Python API for psets, quantities and geometry.
- **Recommendation:** `ifc-lite-core` (MPL is fine) or the shared Part 21 reader from STEP plus an IFC entity mapping. **Feasibility: High** for structure and properties; quantities without exported Qto sets need geometry.

## 3. Shared building blocks for Rezzer

## 4. Licensing summary

**Avoid linking (copyleft that would affect Rezzer):**
- GPL-3: LibreDWG (C), `libredwg-sys`, `uncad`, `kicad-parser`, `kicad-api-rs`, `openscad-rs`, `chipbreaker-gcode`, Python `kiutils`.
- AGPL-3: `brepkit-io`, `openbim-ifc-cli`.
- GPL-2+: `gmsh`.
- Other: `cvkg-stl` (EPL-2.0), `lib_gerber_edit` (non-standard license), `scad` (LGPL-2.0, and it is a generator anyway).

**Weak copyleft, acceptable with care:**
- MPL-2.0 (file-level): `acadrust`, `ifc-lite-core`. Fine to link from MIT/Apache.
- LGPL-2.1 + exception: OCCT, via `opencascade-sys`, `cadrum` (MIT wrapper, but OCCT inside), FreeCAD. Static linking into a Rust binary brings relinking duties. Prefer subprocess use.
- LGPL-3: IfcOpenShell (use as subprocess if at all).
- `serde_kicad_sexpr`: Apache-2.0 OR LGPL-3.0 (can pick Apache), but stale.

**Permissive (preferred):** `dxf`, `cadkit`, `cadmpeg*` (Apache-2.0), `stepq`, `step-io`, `step-p21`, `truck*`, `ruststep`, `stl_io`, `tobj`, `gltf`, `usvg`, `threemf` (0BSD), `lib3mf-core` (BSD-2), `gerber_parser`, `gerberx2`, `gcode`, `g-code`, `tree-sitter-openscad-ng`, `parasolid-core`, `rvt`, ezdxf (Py, MIT).

**Subprocess is fine:** calling a separately installed GPL/LGPL/proprietary program (`dwg2dxf`, `kicad-cli`, `openscad`, `freecadcmd`, ODA File Converter) keeps Rezzer under its own license. Do not bundle GPL binaries in Rezzer's release archive without checking distribution terms; ODA File Converter cannot be redistributed freely.
