# Rezzer research: document and office formats (Rust)

Date: 2026-10-16. Scope: document/office formats for a local, open-source MCP server that converts files to Markdown.

Sources and confidence labels:

- **[crates.io]** = version, release date, license, downloads from the crates.io API, queried 2026-10-16.
- **[GH]** = stars, creation date, last push from the GitHub API, queried 2026-10-16.
- **[README]** = capability claim taken from the project README. Not tested by us.
- **[src]** = verified in the source code on GitHub or docs.rs.
- **[unverified]** = from memory or inference, not checked.

"Pure Rust" means no C/C++ library has to be linked or shipped. Downloads are all-time / last 90 days.

---

## 0. Headline findings

1. **Kreuzberg is now "Xberg".** `kreuzberg-dev/kreuzberg` is gone; `kreuzberg-dev/kreuzberg-lts` says "Kreuzberg v4 LTS (legacy; superseded by xberg for v5+)". The successor is **xberg-io/xberg** (crate `xberg` 1.3.10, 2026-10-13, MIT, 9,420 stars [GH]). **Xberg already ships `xberg mcp`, an MCP server (stdio/HTTP) for 107 formats [README].** That overlaps almost all of Rezzer's purpose. Rezzer must either depend on it, borrow from it, or justify a different niche: Mermaid diagrams, an explicit formula section, small single binary, Markdown-first output quality.
2. **Several "file to Markdown for LLMs" Rust projects appeared in 2025-2026**, often with an MCP server or agent skill: Xberg (MCP), pdf_oxide (`pdf_oxide_mcp`), anydoc by Firecrawl (agent skill, 22.9k stars, created 2026-08-03), office_oxide, undoc/unpdf (iyulab). Most are very young and release very often.
3. **Pure-Rust coverage is now good enough** for PDF (text layer), DOCX, DOC, XLSX/XLS/XLSB/ODS (with formulas), PPTX, PPT, ODP, RTF, EPUB, HTML, CSV, email. No LibreOffice, Java or Python is needed. The gaps are **OCR** (Tesseract is C, or ONNX models), **charts and diagrams to Mermaid** (no crate does this), and **ODT** (no strong standalone crate).
4. **PostScript/EPS no longer needs Ghostscript (AGPL).** `stet` is a pure-Rust PostScript Level 3 interpreter (Apache-2.0 OR MIT), but it is young (17 stars, first release 2026-03-01).
5. **License traps**: `epub` (GPL-3.0), `html2md` (GPL-3.0+), `markitdown` Rust crate (MIT itself, but depends on GPL `html2md`), `mupdf` (AGPL-3.0), Ghostscript (AGPL), `tabula` (AGPL), `pdftotext` (GPL), `rexiv2` (GPL-3.0+), `chardet` (LGPL-3.0). Xberg optional features `wordperfect` (vendored libwpd/librevenge, MPL-2.0/LGPL) and `heic` (libheif, LGPL [unverified for the exact license of the vendored build]).

| Option | Version / date | License | Notes |
|---|---|---|---|
| **stet** (+ stet-pdf, stet-render, stet-cli) | 0.8.7, 2026-10-15 | Apache-2.0 OR MIT | Pure-Rust PostScript Level 3 interpreter + PDF reader, renders PS/EPS to PNG or PDF, embeds 35 URW fonts, `stet text` command prints text a file shows [README]. 17 stars, first release 2026-03-01, 20 versions. | hayro-postscript | 0.1.0, 2026-04-12 | Apache-2.0 OR MIT | Only a PostScript scanner (used for fonts/CMaps), not an interpreter. |

## 13. Main risks

1. **Product overlap with Xberg** (MIT, MCP server, 107 formats) and anydoc (Firecrawl, 22.9k stars). Rezzer's differentiation must be clear.
2. **Maturity**: pdf_oxide (11 months, 627 open issues, pre-1.0), anydoc (2.5 months), undoc/unpdf/office_oxide (under 1 year, weekly breaking minors), stet (7 months, 17 stars), pptx-to-md (6 stars). Pin versions, wrap each behind our own trait, keep a golden-file test corpus.
3. **License contamination**: check every transitive dependency with `cargo-deny` (block GPL/AGPL/LGPL). Known traps listed in section 0.
4. **OCR** has no permissive, pure-Rust, high-quality option yet. Tesseract (C++) or ONNX Runtime add native libs per platform; decide whether OCR is in scope for v1.
5. **Native libs on 3 platforms**: avoid pdfium/Tesseract/libheif in the default build; keep them optional features.
6. **Diagrams to Mermaid** are entirely our own work (charts, SmartArt, Visio not covered here).
7. Pure-Rust PDF table detection is heuristic; expect quality gaps vs docling-style ML models.
